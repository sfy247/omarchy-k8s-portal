# GitOps and Argo CD

Back to [Home](index.md).

**Git is the source of truth.** Argo CD on the hub continuously pulls
`omarchy-k8s-platform` from GitHub and makes every cluster match it. You change
a cluster by pushing a commit, not by running `kubectl apply`.

## App of apps

Ansible applies **one** Application by hand: `root`. Everything else is
created by Argo CD from Git, in layers.

With only dev enabled that's **12 Applications**. Each extra environment adds 8
more: one `env-<name>`, four apps and three add-ons.

## ApplicationSets and generators

| ApplicationSet | Generator | Creates |
|---|---|---|
| `environments` | **clusters** with label `environment` | `env-<env>` per registered worker |
| `cert-manager`, `envoy-gateway`, `gateway` | **clusters** with label `addons=enabled` | one per cluster, hub included |
| `hello-world-<env>` | **matrix**: clusters (`environment=<env>`) × **git directories** `apps/hello-world/*` | one per app in that environment |

**Registering a cluster is what turns an environment on.** Ansible creates the
cluster secret; the generators notice it and create the apps.

## Cluster secrets carry the settings

The platform repo contains no domain, hostname or port. Ansible writes them as
annotations on each cluster's registration, and ApplicationSets read them with
`{{index .metadata.annotations "lab/domain"}}`.

How these annotations get from `lab.yml` into Argo CD is drawn in [01 Ansible Layout and Best Practices](01%20Ansible%20Layout%20and%20Best%20Practices.md).

| Label / annotation | Hub | dev | Used by |
|---|---|---|---|
| `environment` | — | `dev` | `environments`, `hello-world-dev` |
| `addons` | `enabled` | `enabled` | add-on ApplicationSets |
| `lab/domain` | `<domain>` | `dev.<domain>` | app hostnames |
| `lab/gateway-hostname` | `argocd.<domain>` | `*.dev.<domain>` | gateway listener + certificate |
| `lab/gateway-http-nodeport` / `-https-` | 31080 / 31443 | same | EnvoyProxy service |
| `lab/argocd-route` | `true` | `false` | Argo CD HTTPRoute |

All apps use **automated sync with prune and self-heal**: manual changes in a
cluster get reverted. To change something, change Git.

> [!warning] Code changes vs config changes
> Argo CD deploys **manifests**. A change to an app's **code** also needs a new
> image: run `make images` in omarchy-k8s-ansible, or bump `image.tag` in the
> app's values file for a proper release. See [07 Operations Runbook](07%20Operations%20Runbook.md).

## Where things come from

| Thing | Source |
|---|---|
| Argo CD itself | Ansible (`argocd` role, Helm) |
| Cluster registrations + annotations | Ansible (`argocd_clusters`) |
| `platform` project + `root` app | Ansible (`gitops_bootstrap`) |
| Everything else | Git, via Argo CD |
